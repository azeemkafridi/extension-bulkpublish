# Changelog

## 0.1.0 (2026-08-27)

Initial release — the BulkPublish WordPress plugin's composer, rebuilt as a cross-browser extension with WXT (Chrome MV3 and Firefox from one codebase).

- **Popup composer** ported from the WordPress plugin (v1.5.0): channel pills + popover selector with channel sets, per-platform caption overrides, live character limits measured against the resolved caption, scheduling with the browser's timezone, and the "Require approval" flow. Publish-now keeps the plugin's two-step shape — create as draft, then publish — skipping the publish call when the post comes back held for approval, and carrying the created post's id through a failed publish so retry never duplicates the draft.
- **Architecture shift from the plugin:** WordPress kept the API key on the server behind a REST proxy; an extension has no server, so the key lives in `storage.local` (never `storage.sync` — a synced key would replicate to every signed-in browser) and the popup calls `app.bulkpublish.com` directly. Host permissions make extension pages CORS-exempt, so no background message-shuttling layer exists at all — the background script owns only the context menus.
- **Context-menu sharing** on pages, selections, and images. The click stores a prefill in `storage.session` (the right lifetime for "the thing you just right-clicked") and opens the popup; where `action.openPopup()` isn't available it falls back to a small standalone window.
- **Page prefill and tokens.** The caption prefills from the page title/URL, or the selection when there is one. Of the WordPress plugin's server-resolved token set, only `%%title%%` and `%%link%%` survive — they're the only ones with a meaning outside a WP post — and they resolve against the current page at submit time.
- **Media** uploads on selection: simple `POST /api/media` up to 100 MB, the multipart create → presigned parts → complete flow (10 MB parts, abort on failure, per-part progress) above it. "Grab images from this page" collects the page's ≥200px images and fetches the chosen one *from inside the page* — the page can read its own images where the extension's origin could not.
- **Recent tab**: latest 20 posts with approve/reject (with reason), retry, delete, and expandable per-channel status; status polling every 4s while anything is pending or publishing.
- **Costs and quotas**: the plugin's pre-publish table, with the X dcent math extracted to a pure module. Server price sheet wins over the built-in fallbacks.
- **Link tracking is a three-option control** (Account default / On / Off) because omitting `linkTrackingOverride` inherits the workspace setting — an untouched control must not send `false`.
- **Recent is one compact row per post.** A media thumbnail (with a `+N` badge when a post carries more, and a play glyph for video), the platforms, state and approval badges, a two-line caption, and when it went out. Every action — status, approve, reject, retry, delete — moved into a kebab menu that only lists what the post actually supports, so a row of buttons no longer grows and shrinks per post. The menu is the same component as the header's, which also fixed the caption pushing the control off-screen: the body needed `min-width: 0` to let a long unbroken word wrap instead of stretching the row.
- **Settings sits on one rhythm.** Each setting is now heading → control → hint with consistent spacing, replacing markup that leaned on `.bp-field` (which has no gap) and put a `<code>`, a 28px icon button and a ghost button in one row where none of the three shared a height or a baseline. The masked key fills its row at the same 32px as the button beside it, and Disconnect is pulled back by its own padding so its label lines up with everything above rather than floating indented.
- **Detaching media reclaims the storage it used.** Removing an attachment now deletes the uploaded file, instead of leaving it in the library counting against the storage quota until the server's three-month sweep found it. This is only safe under conditions worth stating: `posts.mediaFiles` is a JSONB array rather than a foreign key and the server's DELETE does not reference-check, so deleting a file a post points at would leave that post referencing nothing. Everything in the composer was uploaded by the composer (there is no library picker) and uploads are never de-duplicated server-side, so the file is ours alone — right up until a post is created from it, after which detaching only removes it locally. Cleanup is best-effort: the retention sweep, which names "uploads abandoned before submit" as its case, remains the backstop for a popup closed mid-compose.
- **The composer survives the popup closing.** A popup is dismissed by any click outside it, so this is how a session normally ends, not an edge case — yet attached media, channel picks and the schedule were all being dropped, and thumbnails were stored as `blob:` URLs that die with the document. The draft now keeps all of it and uses the durable URLs the upload returns. An untouched prefill is still discarded when you have moved to a different page, so last page's title never captions this one, and a published draft is cleared so the next open cannot re-send it.
- **Scrollbars are thin with a transparent track.** A default desktop scrollbar is ~15px of a 400px popup and parked a grey trough against the header. (The colour needed its own tokens: `tokens.css` scopes the palette to `.bulkpublish-root`, but the element that owns the popup's scrollbar is `<html>` above it, where those variables resolve to nothing and take the whole declaration down with them.)
- **A card for the page you're on, at the top of Compose.** It shows the page's own sharing metadata — social image, favicon, site name, title, summary — with one-tap chips to insert the title, link, summary, or your current selection into the caption. All of it is read out of the tab by an injected function: the browser that already has the page open does the extraction, so no URL is ever handed to our server to fetch and scrape, which would otherwise put a crawler in the request path of every popup open. The card is dismissible and everything below it works without it — composing something unrelated to the current tab is a first-class case, not a workaround.
- **Section navigation moved into a menu.** Compose / Recent / Settings live behind a single control in the header, with the current section named beside the logo. The header also got an explicit background: it is `position: sticky`, and `background: inherit` was resolving to transparent, so the composer scrolled visibly *through* it.
- **The primary action is pinned.** Compose runs ~940px inside a popup Chrome caps at 600px, which left Publish/Schedule roughly 300px below the fold — you composed, then scrolled past the cost table to send. The actions now sit in a sticky footer along with the character counter, so both stay reachable at any scroll position and the count is visible even when the caption itself is scrolled away.
- **Caption tokens are chips again, not instructions.** The port had replaced the WordPress plugin's token UI with a line of text telling people to type `%%title%%` by hand; they are clickable chips once more, inserting at the caret so a token can be dropped mid-sentence.
- **Field borders use the app's own gray.** `tokens.css` points `--bp-wp-border` at WordPress's admin control gray (#8c8f94) so inputs stay visible against wp-admin's white — there is no wp-admin here, and that dark hairline read far heavier than the soft "Before you publish" panel beneath it. The token is retargeted at `--bp-stone-200` for the extension.
- **App icons come from the plated 1:1 logo.** They were first generated from the 766×474 wordmark squashed into squares, so every size shipped distorted and bleeding off its edges; `plugin-logo.svg` exists upstream precisely because directories need a square mark on a background plate.
- **All 16 platform icons ship**, including Snapchat — the WordPress plugin's icon set stopped at 15, so a Snapchat channel there fell back to a letter badge. The glyph is the same file the app and marketing site use, and its tint carries a 0.25 alpha rather than the other platforms' 0.1 (matching the app) because Snapchat yellow all but disappears at 0.1. The tint lives in `popup.css`, not the shared `tokens.css`, so re-copying that file from the plugin can't silently drop it.
- **Character limits now cover every platform the server enforces.** The list inherited from the WordPress plugin predated Reddit, Discord, Telegram, Tumblr, and Snapchat, so selecting any of them gave no counter and no pre-submit block — an over-length caption failed server-side at publish instead. Snapchat's 160 (Spotlight descriptions) is the tightest limit of any platform, tighter than X's 280, so its absence was the most visible. A test pins the table against the API's platform enum.
- Not surfaced: the WordPress plugin's auto-share hooks, automation rules, and WP content dashboard — all of them are WordPress-side concepts with no browser equivalent.
- Pure logic (`lib/`: API client, post-body assembly, cost math, multipart orchestration, prefill) is browser-global-free and covered by 55 `node:test` cases.
